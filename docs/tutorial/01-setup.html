Setup & Prerequisites

Install the toolchain, clone the repo, and create the Snowflake schema before writing a single line of app code.

Prerequisites

🐍

Python 3.11+

uv manages the interpreter — you don't need it pre-installed.

📦

uv

Fast Python package manager. Replaces pip + venv + pip-tools.

❄️

snow CLI

Snowflake CLI for running SQL, deploying Streamlit apps.

🐙

GitHub account

Public repo. No PAT needed — Snowflake uses OAuth2 for git; CI uses OIDC.

Install the toolchain

💡
Why uv? uv resolves + installs the full dependency tree in ~1s (vs ~30s for pip). It also pins Python 3.11 via .python-version so every dev gets the same interpreter without pyenv/asdf. The lockfile (uv.lock) guarantees reproducible builds in CI and on colleagues' machines.
💡
Why container runtime? The SiS container runtime gives you a full Python environment with pip-installable packages (via pyproject.toml). Warehouse runtime is limited to a fixed Anaconda channel. Container runtime also supports custom system dependencies if you ever need them.
bash
# Install uv (macOS / Linux)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install snow CLI
pip install snowflake-cli

# Verify
uv --version     # 0.x.x
snow --version   # 3.x.x

Option A — GitHub Codespaces (zero local setup)

The repo includes a .devcontainer/devcontainer.json that pre-installs uv, snow CLI, Python 3.11, and VS Code extensions. Click the badge in the README to open a ready-to-code browser environment in seconds:

bash — after Codespace starts
make test   # 55 unit tests, no credentials needed — runs in the Codespace
💡
Set Codespaces secrets to enable Snowflake-touching targets (make dev, make setup, make deploy): SNOWFLAKE_DEFAULT_CONNECTION_NAME, GIT_SIS_DATABASE, GIT_SIS_SCHEMA. Unit tests work without any secrets.

Option B — Local development

Clone and install dependencies

bash
git clone https://github.com/waldekkot/git-sis
cd git-sis
make install   # uv sync + pre-commit hooks (no Snowflake needed)
💡
direnv (optional but recommended) automatically loads environment variables when you cd into the project — no more forgetting to set SNOWFLAKE_DEFAULT_CONNECTION_NAME before running make targets.
bash — one-time direnv setup
brew install direnv   # macOS; add eval "$(direnv hook zsh)" to ~/.zshrc
cp .envrc.example .envrc
# Edit .envrc: set SNOWFLAKE_DEFAULT_CONNECTION_NAME + schema vars
direnv allow

Configure your Snowflake connection

Add a named connection using the interactive wizard — or edit ~/.snowflake/connections.toml directly:

bash — interactive wizard (recommended)
snow connection add
# Follow the prompts: account, username, authenticator, warehouse, role
~/.snowflake/connections.toml — externalbrowser (SSO)
[my-snowflake]
account       = "sfseeurope-myaccount"
user          = "my_user"
authenticator = "externalbrowser"   # opens SSO in browser — recommended
warehouse     = "COMPUTE_WH"
role          = "SYSADMIN"
bash — verify connection
snow connection test -c my-snowflake
# Expected: ✔ Connection successful

Create the DEV schema and tables

make setup runs deploy/00_setup_env.sql against your connection — idempotent, safe to re-run. Creates the GIT_SIS schema, ORDERS, and INGEST_LOG.

bash
make setup
# or with a specific connection: make setup CONN=my-snowflake
🌱
Seed sample data for a realistic app experience right after setup:
bash
make seed   # inserts 5 INGEST_LOG rows + 50 ORDERS rows (idempotent)
✅
Pre-commit hooks are already installed by make install. To run all hooks manually against the whole codebase:
bash
make hooks   # uvx pre-commit run --all-files
