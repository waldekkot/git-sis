Local Dev & The Session Seam

Write once, run in two places. The app is identical on your laptop and inside Snowflake — only the session construction differs.

The session seam

app/lib/session.py is the entire seam between environments. get_active_session() only exists inside Snowflake's runtime; if the import fails, we fall back to a CLI-built session.

app/lib/session.py
import os
import streamlit as st
from snowflake.snowpark import Session

@st.cache_resource(show_spinner="Connecting to Snowflake...")
def get_session() -> Session:
    try:
        from snowflake.snowpark.context import get_active_session
        return get_active_session()          # ← inside SiS
    except Exception:
        conn = (
            os.getenv("SNOWFLAKE_DEFAULT_CONNECTION_NAME")
            or "default"
        )
        return Session.builder.config(       # ← local
            "connection_name", conn
        ).create()
💡
@st.cache_resource ensures the session is created once per process. On SiS, Snowflake injects it; locally, the CLI connection is reused. Zero code changes between environments.

TDD workflow & the mock inventory principle

Unit tests combine two in-process tools: the Snowpark local testing framework (real DataFrame emulator) and Streamlit AppTest (UI interaction without a browser). Together they give end-to-end UI + data-layer tests with zero credentials.

Mock inventory principle: mock only what the emulator cannot provide; inject what's configurable.

Need Pattern Why
Snowpark session backend _module_session + seeded_session One emulator per module, tables wiped per test
UUID_STRING built-in uuid_patch fixture Emulator gap, not business logic
uniform, round built-ins @snowflake.snowpark.mock.patch Emulator gap, not business logic
Force a controlled failure MagicMock (one test) Only test that needs inaccessible tables
Session seam itself monkeypatch + unittest.mock Testing the seam, not Snowpark logic
tests/unit/test_app.py — zero-mock UI test
@pytest.fixture()
def snowpark_app(seeded_session, uuid_patch):  # real emulator + UUID patch
    with patch("lib.session.get_session", return_value=seeded_session):
        at = AppTest.from_file(APP_FILE).run()  # Streamlit AppTest in-process
    return at, seeded_session

def test_button_click_writes_500_rows(snowpark_app):
    at, sess = snowpark_app
    with patch("lib.session.get_session", return_value=sess):
        at.button[0].click().run()          # UI interaction
    assert "500" in at.success[0].value     # UI assertion
    assert sess.table(_cfg.ORDERS_TABLE).count() == 500  # real Snowpark assertion
💡
seeded_session is a real Snowpark local testing session, not a stub. count() is a real DataFrame operation. AppTest and the emulator share the same in-process tables — no MagicMock needed for the happy path.

Snowflake local testing framework

Unit tests use Session.builder.config("local_testing", True).create() for an in-process Snowflake emulator — no credentials, no network required. ingest.py uses the DataFrame API exclusively (no session.sql()) so the emulator can run all logic locally.

Snowflake built-ins not yet in the emulator (uniform, round, UUID_STRING) are provided via @snowflake.snowpark.mock.patch and uuid_patch in tests/unit/conftest.py.

tests/unit/conftest.py — shared fixtures
from snowflake.snowpark.mock import patch, ColumnEmulator, ColumnType
from snowflake.snowpark.functions import uniform as sf_uniform, round as sf_round
from snowflake.snowpark.types import LongType, DoubleType
from unittest.mock import patch as mock_patch

# @snowflake.snowpark.mock.patch — registered at module import,
# active whenever the emulator processes uniform() in a DataFrame plan.
@patch(sf_uniform)
def _mock_uniform(start, end, gen) -> ColumnEmulator: ...

@patch(sf_round)
def _mock_round(value, scale=0) -> ColumnEmulator: ...

# ── Module-scoped session: ONE emulator per test module (~30 ms) ──────
# Creates the session + tables once for all tests in the module.
# seeded_session (function-scoped) truncates tables between tests (~2 ms)
# instead of recreating the session per test (~30 ms each).
# This cut setup overhead from ~1.4 s to ~0.1 s across 46 tests.
@pytest.fixture(scope="module")
def _module_session(request) -> Session:
    """One session per module — emulator (local) or real Snowflake (live)."""
    if request.config.getoption("--snowflake-session", default="local") == "local":
        sess = Session.builder.config("local_testing", True).create()
        sess.create_dataframe([], LOG_SCHEMA).write.save_as_table(_cfg.INGEST_LOG_TABLE)
        sess.create_dataframe([], ORDERS_SCHEMA).write.save_as_table(_cfg.ORDERS_TABLE)
        yield sess
        sess.close()
    else:  # live: real Snowflake, disposable schema per module
        ...

@pytest.fixture()
def seeded_session(request, _module_session) -> Session:
    """Wipe both tables before each test, reusing the module session."""
    _module_session.table(_cfg.ORDERS_TABLE).delete()
    _module_session.table(_cfg.INGEST_LOG_TABLE).delete()
    yield _module_session

@pytest.fixture()
def uuid_patch():
    """UUID_STRING not in emulator — only justified unittest.mock."""
    with mock_patch("lib.ingest.call_function",
                    side_effect=lambda _: lit(str(uuid.uuid4()))):
        yield
💡
_module_session is the key performance fix: Session.builder…create() costs ~30 ms. With 46 function-scoped tests that would be ~1.4 s of pure fixture overhead. Two module-scoped sessions cost ~60 ms. Tables are wiped with .delete() (~2 ms) between tests — the same DataFrame API used in production.

Config and table isolation

app/lib/config.py reads table FQNs from an environment variable:

app/lib/config.py
import os

SCHEMA_FQN   = os.getenv("GIT_SIS_SCHEMA", "SNOWFLAKE_LEARNING_DB.GIT_SIS")
ORDERS_TABLE = f"{SCHEMA_FQN}.ORDERS"
INGEST_LOG_TABLE = f"{SCHEMA_FQN}.INGEST_LOG"

Integration tests set GIT_SIS_SCHEMA=SNOWFLAKE_LEARNING_DB.GIT_SIS_TEST_<uuid> per test (function-scoped schema), so they never touch production data and can run in parallel with pytest-xdist. Each schema is dropped automatically after the test. Live unit tests use the same module-scoped pattern with a shared temp schema per test module.

⚠️
Import-by-value trap: Always use from lib import config as _cfg and access _cfg.ORDERS_TABLE at call time. Using from lib.config import ORDERS_TABLE captures the string at import time — test schema overrides won't propagate.
