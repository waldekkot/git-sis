Push to GitHub & Wire Snowflake

Create the GitHub repo, push your code, then connect Snowflake via OAuth2 — one browser click, no secrets to manage.

1. Create the GitHub repo and push

bash
# Create the public repo and push (gh CLI)
gh repo create waldekkot/git-sis --public --source=. --remote=origin --push

# Or if repo already exists
git remote add origin https://github.com/waldekkot/git-sis
git push -u origin main
💡
Why public? A public repo unlocks GitHub's environment protection rules (required reviewers on prod deploy) on all billing plans. It also makes the blueprint directly shareable with customers and teammates — no access requests needed. There are no secrets in the repo (all auth is OIDC/OAuth2-based).

2. Connect Snowflake to GitHub (OAuth2 — one click)

Snowflake authenticates to GitHub using the built-in Snowflake GitHub App. No Personal Access Token, no client secret, no rotation — Snowflake manages the OAuth2 tokens automatically. Each user authorizes once in their browser.

💡
Why OAuth2 instead of PAT?
• No secret storage: PATs must be stored in a Snowflake SECRET, rotated before expiry, and shared across CI/manual flows. OAuth2 eliminates all of that.
• Per-user identity: each developer authorizes individually. Audit logs show who fetched, not a generic service account.
• No expiry anxiety: the GitHub App handles token refresh transparently.

Option A — via Snowsight (recommended)

  1. Open Snowsight → Workspaces → New workspace
  2. In the Files tab, click Connect Git Repository
  3. Complete the GitHub OAuth authorization (one-click browser popup)
  4. Select the repo waldekkot/git-sis and branch main

That's it. Subsequent FETCH operations work automatically.

Option B — via shell runner

bash
# Creates the API INTEGRATION + GIT REPOSITORY with OAuth2
scripts/10_setup.sh --with-git -c oregon-sedemo

After running this, open any Workspace and authorize the GitHub App when prompted. The script creates:

SQL — what 10_setup.sh --with-git creates
-- API Integration (ACCOUNTADMIN)
CREATE API INTEGRATION IF NOT EXISTS git_api_waldekkot
    API_PROVIDER = git_https_api
    API_ALLOWED_PREFIXES = ('https://github.com/waldekkot')
    ENABLED = TRUE;

-- GIT REPOSITORY (SYSADMIN) — no GIT_CREDENTIALS needed for OAuth2
CREATE GIT REPOSITORY IF NOT EXISTS SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO
    API_INTEGRATION = git_api_waldekkot
    ORIGIN = 'https://github.com/waldekkot/git-sis';

-- Verify clone succeeded
ALTER GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO FETCH;
SHOW GIT BRANCHES IN GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO;
💡
No GIT_CREDENTIALS parameter: with OAuth2, the user's browser-authorized token is used transparently. The GIT_CREDENTIALS keyword is only needed for PAT-based auth (the legacy path).

3. Verify the git-sync

bash — verify from CLI
snow sql -c oregon-sedemo -q "
ALTER GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO FETCH;
SHOW GIT BRANCHES IN GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO;"
# Expected: a row for 'main' with the current commit SHA
✅
Git wiring is optional. The primary deploy path (snow streamlit deploy) doesn't need a GIT REPOSITORY at all — it uploads files directly. The git wiring enables Workspace git-sync (push/pull from Snowsight) and make deploy-git (pull-based refresh).
