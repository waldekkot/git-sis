Push to GitHub & Wire Snowflake

Create the GitHub repo, push your code, then let Snowflake clone it via a GIT REPOSITORY object — authenticated with a stored PAT secret.

1. Create the GitHub repo and push

bash
# Create the private repo and push (gh CLI)
gh repo create waldekkot/git-sis --private --source=. --remote=origin --push

# Or if repo already exists
git remote add origin https://github.com/waldekkot/git-sis
git push -u origin main

2. Create a GitHub Personal Access Token

Snowflake needs a PAT to clone your private repo. Use a classic PAT with repo scope — fine-grained tokens have known issues with Snowflake's git_https_api provider.

  1. Go to GitHub → Settings → Developer Settings → Personal access tokens → Tokens (classic)
  2. Click Generate new token (classic)
  3. Select scope: repo (full control of private repos)
  4. Copy the token — you won't see it again
⚠️
Never paste your token in chat or commit it to git. Store it only in the Snowflake SECRET created in the next step.

3. Store the PAT as a Snowflake SECRET

Run this from your local terminal — not in Snowsight (to ensure you're hitting the correct account):

bash — run in your terminal
snow sql -c oregon-sedemo -q "
CREATE OR REPLACE SECRET SNOWFLAKE_LEARNING_DB.GIT_SIS.GITHUB_PAT
    TYPE = password
    USERNAME = 'waldekkot'
    PASSWORD = '<your-classic-github-pat>';
"

Verify the created_on timestamp changed (proves the right account was updated):

bash
snow sql -c oregon-sedemo -q \
  "SHOW SECRETS IN SCHEMA SNOWFLAKE_LEARNING_DB.GIT_SIS" \
  | grep GITHUB_PAT
✅
The created_on timestamp is your truth signal. If it didn't change, your edit landed in the wrong account. Always use snow sql -c <connection> to guarantee the right target.

4. Create the API Integration and GIT REPOSITORY

The bootstrap script handles both (requires ACCOUNTADMIN for the API integration):

bash
# First-time only: creates API integration + git repo (then deploys)
scripts/deploy.sh --bootstrap -c oregon-sedemo

Or manually — see deploy/10_git_and_streamlit.sql sections 1 and 2:

SQL — create API integration (ACCOUNTADMIN)
USE ROLE ACCOUNTADMIN;
CREATE API INTEGRATION IF NOT EXISTS git_api_waldekkot
    API_PROVIDER           = git_https_api
    API_ALLOWED_PREFIXES   = ('https://github.com/waldekkot')
    ALLOWED_AUTHENTICATION_SECRETS = (SNOWFLAKE_LEARNING_DB.GIT_SIS.GITHUB_PAT)
    ENABLED                = TRUE;
GRANT USAGE ON INTEGRATION git_api_waldekkot TO ROLE SYSADMIN;

USE ROLE SYSADMIN;
CREATE GIT REPOSITORY IF NOT EXISTS SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO
    API_INTEGRATION  = git_api_waldekkot
    GIT_CREDENTIALS  = SNOWFLAKE_LEARNING_DB.GIT_SIS.GITHUB_PAT
    ORIGIN           = 'https://github.com/waldekkot/git-sis';

-- Verify clone succeeded
ALTER GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO FETCH;
SHOW GIT BRANCHES IN GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO;
💡
Expected output from SHOW GIT BRANCHES: a row for main with the current commit SHA. If you see "Operation 'clone' is not authorized", the PAT token is missing or has wrong scope.
