Deploy to Streamlit-in-Snowflake

Create the git-connected Streamlit app on container runtime. Three SQL statements, one shell command, zero file uploads.

First-time bootstrap

Run --bootstrap once — it creates the API integration and GIT REPOSITORY, then runs the deploy loop.

bash
scripts/deploy.sh --bootstrap -c oregon-sedemo

The bootstrap script runs:

  1. USE ROLE ACCOUNTADMIN → create git_api_waldekkot API integration
  2. Grant USAGE to SYSADMIN, create APP_REPO GIT REPOSITORY
  3. Run the deploy loop (FETCH + CREATE STREAMLIT + ADD LIVE VERSION)
💡
Container runtime requirements: app/pyproject.toml must exist in the app source directory (not repo root), and EXTERNAL_ACCESS_INTEGRATIONS = (PYPI_ACCESS_INTEGRATION) must be set in the CREATE STREAMLIT statement. Without either, the container startup fails.

The deploy SQL

SQL — deploy/10_git_and_streamlit.sql (section 3)
-- Pull latest commit from GitHub
ALTER GIT REPOSITORY SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO FETCH;

-- Snapshot app/ dir from the cloned branch
CREATE OR REPLACE STREAMLIT SNOWFLAKE_LEARNING_DB.GIT_SIS.INGEST_CONSOLE
    FROM '@SNOWFLAKE_LEARNING_DB.GIT_SIS.APP_REPO/branches/main/app/'
    MAIN_FILE         = 'streamlit_app.py'
    QUERY_WAREHOUSE   = COMPUTE_WH
    RUNTIME_NAME      = 'SYSTEM$ST_CONTAINER_RUNTIME_PY3_11'
    COMPUTE_POOL      = SYSTEM_COMPUTE_POOL_CPU
    EXTERNAL_ACCESS_INTEGRATIONS = (PYPI_ACCESS_INTEGRATION)
    TITLE             = 'Ingestion Ops Console';

-- Activate the app
ALTER STREAMLIT SNOWFLAKE_LEARNING_DB.GIT_SIS.INGEST_CONSOLE
    ADD LIVE VERSION FROM LAST;

Redeploy after a code change

Every subsequent deploy after a git push is just the three-step loop — no --bootstrap:

bash
git push && scripts/deploy.sh -c oregon-sedemo
✅
On push to main, GitHub Actions also runs this automatically — see Chapter 5 (CI/CD).

Verify the deployment

bash
# Get the app URL and open it
scripts/verify.sh --open -c oregon-sedemo

# Or just print the URL
snow streamlit get-url -c oregon-sedemo \
  SNOWFLAKE_LEARNING_DB.GIT_SIS.INGEST_CONSOLE
💡
EXECUTE STREAMLIT is not supported on container runtime (only on warehouse runtime). Browser verification is the correct approach — open the URL and confirm the app is Active with live KPI tiles.

Teardown (cleanup)

bash
# Drop all objects (STREAMLIT, GIT REPOSITORY, SECRET, schema, API integration)
snow sql -c oregon-sedemo -f deploy/99_cleanup.sql

Cleanup is idempotent — safe to re-run. PYPI_ACCESS_INTEGRATION is a shared resource and is intentionally not dropped.
