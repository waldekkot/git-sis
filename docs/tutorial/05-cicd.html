Pre-commit Hooks & Secretless CI/CD

Lock quality gates on every commit. OIDC auth means zero stored secrets — GitHub Actions deploys to SiS with short-lived tokens that expire in minutes.

Part A — Pre-commit hooks

One-time setup

bash
make install   # = uv sync + uv run pre-commit install (one-time setup)

Test all hooks manually

bash
make hooks   # = uvx pre-commit run --all-files
# All 5 hook groups should print "Passed"

The .pre-commit-config.yaml

.pre-commit-config.yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-toml

  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.15.15
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

  - repo: local
    hooks:
      - id: ty
        name: ty (type check)
        entry: uv run ty check app/lib/
        language: system
        types: [python]
        pass_filenames: false

      - id: import-linter
        name: import-linter (lib must not import streamlit)
        entry: bash -c 'cd app && uv run --project .. lint-imports'
        language: system
        types: [python]
        pass_filenames: false

      - id: pytest-unit
        name: pytest unit (no Snowflake)
        entry: uv run pytest tests/unit/ --tb=short -q
        language: system
        types: [python]
        pass_filenames: false  # 55 tests · ~2s

TDD loop summary

The full local-to-production cycle has four phases. Each phase is one make command:

  1. Write a failing test in tests/unit/
  2. make test — red (≈2s, no credentials)
  3. Implement the minimum code to pass
  4. make test — green
  5. Refactor. make test stays green.
  6. make test-full — unit + integration against real Snowflake (~15s total, parallel)
  7. git commit — pre-commit gates run automatically
  8. git push — CI fires: unit tests → integration tests (real Snowflake) → SiS deploy

Part B — GitHub Actions CI/CD (OIDC — zero secrets)

The pipeline uses Workload Identity Federation (OIDC) instead of stored secrets. GitHub mints a short-lived JWT; Snowflake validates it against the registered subject claim. No PATs, no rotation, no expiry anxiety.

💡
How OIDC works in this pipeline:
1. GitHub Actions requests a JWT from its built-in OIDC provider
2. The snowflakedb/snowflake-cli-action passes this token to Snowflake
3. Snowflake verifies the token’s sub claim matches the SERVICE user’s WORKLOAD_IDENTITY_PROVIDER + authorized subject
4. A session is granted — no password or key ever leaves GitHub

GitHub Environments

Three environments control OIDC subject scoping and approval gates:

Environment SERVICE user OIDC subject Protection
ci CI_SVC_CI repo:waldekkot/git-sis:environment:ci none (auto-approve)
preview CI_SVC_PREVIEW repo:waldekkot/git-sis:environment:preview none (PR ephemeral)
prod CI_SVC_PROD repo:waldekkot/git-sis:environment:prod Required reviewer

The prod environment has a required reviewer gate: the pipeline pauses at deploy-to-sis until a maintainer approves. This prevents untested code from reaching users even if tests pass (defense-in-depth).

The .github/workflows/ci.yml has five jobs in sequence (with the unit jobs running in a 2-Python matrix in parallel):

Job When Auth What it validates
unit-tests-311 Every push + PR None Emulator + ruff + import-linter + check-docs (Python 3.11)
unit-tests-312 Every push + PR None Same suite on Python 3.12 (forwards-compat signal)
integration-tests Push to main OIDC (env:ci) Real Snowflake, isolated GIT_SIS_TEST_<uuid> schemas, parallel
dcm-plan Push to main OIDC (env:ci) Previews DDL changes; blocks on destructive ops (add [skip-dcm] until set up)
deploy-to-sis Push to main OIDC (env:prod) Deploys app + commits MAIN_<sha> version alias + pytest smoke tests
💡
Concurrency groups prevent deploy races: pushes to main queue (the second waits for the first to finish); PR builds cancel stale runs (only the latest commit matters for previews). This is critical when ALTER STREAMLIT COMMIT VERSION is in the mix.

The CI workflow (key structure)

.github/workflows/ci.yml (key structure)
name: CI

on:
  push:
    branches: [main]
  pull_request:

# Queue deploys to main; cancel stale PR runs
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  # Reusable workflow called twice: Python 3.11 (SiS runtime) + 3.12 (compat)
  unit-tests-311:
    uses: ./.github/workflows/reusable-unit-tests.yml
    with: { python-version: "3.11" }

  unit-tests-312:
    uses: ./.github/workflows/reusable-unit-tests.yml
    with: { python-version: "3.12" }

  integration-tests:
    needs: [unit-tests-311, unit-tests-312]
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    environment: ci                     # ← scopes OIDC subject to ci env
    steps:
      - uses: actions/checkout@<sha>   # SHA-pinned (Dependabot maintains)
      - uses: snowflakedb/snowflake-cli-action@<sha>
        with: { use-oidc: true, oidc-token-name: SNOWFLAKE_CONNECTIONS_CI_TOKEN }
      - run: uv run pytest tests/integration/ -v -n 5

  dcm-plan:
    needs: integration-tests
    environment: ci
    steps:
      - run: snow dcm plan --project-name $DB.$SCHEMA.GIT_SIS_DCM --source dcm/
        continue-on-error: true  # non-blocking until DCM project object is created

  deploy-to-sis:
    needs: [integration-tests, dcm-plan]
    environment: prod               # ← requires reviewer approval
    steps:
      - run: scripts/30_deploy.sh -c ci
      - run: |                      # commit MAIN_<sha> version alias (rollback point)
          snow sql -c ci -q "ALTER STREAMLIT ... ADD VERSION IF NOT EXISTS MAIN_$SHA FROM LAST"
      - run: uv run pytest tests/smoke/ -v
        env: { GIT_SIS_APP_URL: ${{ steps.app-url.outputs.url }} }

The release workflow (tag → versioned deploy)

Pushing a v*.*.* tag triggers .github/workflows/release.yml, which deploys + commits an immutable Streamlit version alias:

.github/workflows/release.yml (key steps)
# Triggered by: git tag v1.2.3 && git push origin v1.2.3
on:
  push:
    tags: ['v*.*.*']

jobs:
  release:
    environment: prod
    steps:
      - run: scripts/30_deploy.sh -c ci --commit "${{ github.ref_name }}"
        # v1.2.3 → V1_2_3 (Snowflake identifier rules)
        # Commits as a stable, immutable version alias
💡
Version aliases available for rollback:
• MAIN_<sha> — every CI deploy to main (automatic)
• V1_2_3 — every tagged release (manual)
Rollback: ALTER STREAMLIT ... SET DEFAULT_VERSION = <alias>; — seconds, no redeploy. See docs/runbook.md.
🚀
Full secretless cycle: git commit (pre-commit) → git push (OIDC CI: unit → integration → approval → deploy) → git tag v1.0.0 && git push origin v1.0.0 (immutable version). Zero secrets stored. Rollback in seconds.
