Pre-commit Hooks & GitHub Actions

Lock quality gates on every commit. Auto-deploy to SiS on every push to main — zero manual steps after the first setup.

Part A — Pre-commit hooks

One-time setup

bash
make install   # = uv sync + uv run pre-commit install (one-time setup)

Test all hooks manually

bash
make hooks   # = uvx pre-commit run --all-files
# All 8 hooks should print "Passed"

The .pre-commit-config.yaml

.pre-commit-config.yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-toml

  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.15.15
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

  - repo: local
    hooks:
      - id: ty
        name: ty (type check)
        entry: uv run ty check app/lib/
        language: system
        types: [python]
        pass_filenames: false

      - id: pytest-unit
        name: pytest unit (no Snowflake)
        entry: uv run pytest tests/unit/ --tb=short -q
        language: system
        types: [python]
        pass_filenames: false  # 46 tests · ~3s

TDD loop summary

The full local-to-production cycle has four phases. Each phase is one make command:

  1. Write a failing test in tests/unit/
  2. make test — red (≈2s, no credentials)
  3. Implement the minimum code to pass
  4. make test — green
  5. Refactor. make test stays green.
  6. make test-full — unit + integration against real Snowflake (~15s total, parallel)
  7. git commit — pre-commit gates run automatically
  8. git push — CI fires: unit tests → integration tests (real Snowflake) → SiS deploy

Part B — GitHub Actions CI/CD

The .github/workflows/ci.yml has three jobs in sequence:

Job When What it validates
unit-tests Every push + every PR DataFrame logic against the Snowpark emulator + ruff lint. No credentials needed.
integration-tests Push to main only Same logic against the real Snowflake engine. Creates and drops a disposable GIT_SIS_TEST_<uuid> schema — never touches production data.
deploy-to-sis Push to main only Deploys the app only after both test layers pass. Uses scripts/30_deploy.sh → snow streamlit deploy.
💡
Why integration tests only on main? PRs (especially from forks) don't have access to the SF_PAT_TOKEN GitHub Secret, and running real Snowflake compute on every PR adds cost and latency. Unit tests give fast feedback on PRs; integration tests are the final gate before production deploy.

Add the required GitHub Secret

  1. Read your Snowflake Programmatic Access Token value from the local token file
  2. Go to your GitHub repo → Settings → Secrets and variables → Actions
  3. Click New repository secret
  4. Name: SF_PAT_TOKEN, Value: the raw token string
⚠️
Note on token expiry: Snowflake PAT tokens may have an expiration date. If the deploy job starts failing with auth errors, regenerate the token and update the GitHub Secret.

The CI workflow

.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  unit-tests:
    name: Unit tests + lint (no Snowflake)
    # Runs on every push and every PR — no credentials required.
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v4
        with: { version: "latest", enable-cache: true, cache-dependency-glob: "uv.lock" }
      - run: uv sync
      - run: uv run pytest tests/unit/ -v --tb=short
      - run: uv run ruff check app/

  integration-tests:
    name: Integration tests (real Snowflake)
    # Runs after unit tests pass, on push to main only.
    # Creates and drops a disposable GIT_SIS_TEST_ schema.
    runs-on: ubuntu-latest
    needs: unit-tests
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v4
        with: { version: "latest", enable-cache: true, cache-dependency-glob: "uv.lock" }
      - run: uv sync
      - name: Configure Snowflake CI connection
        run: |
          echo "$SF_PAT_TOKEN" > /tmp/sf_token.txt
          mkdir -p ~/.snowflake
          printf '[connections.ci]\naccount = "sfseeurope-wkot_demo1"\n\
user = "wkot"\nauthenticator = "PROGRAMMATIC_ACCESS_TOKEN"\n\
token_file_path = "/tmp/sf_token.txt"\n' > ~/.snowflake/config.toml
          chmod 0600 ~/.snowflake/config.toml
        env: { SF_PAT_TOKEN: "${{ secrets.SF_PAT_TOKEN }}" }
      - name: Run integration tests
        # Each test gets its own GIT_SIS_TEST_ schema (function-scoped).
        # -n 5: 5 workers run schemas in parallel, cutting ~60s → ~12s.
        run: uv run pytest tests/integration/ -v --tb=short --no-cov -n 5
        env: { SNOWFLAKE_DEFAULT_CONNECTION_NAME: ci }

  deploy-to-sis:
    name: Deploy to SiS (main only)
    # Deploys only after BOTH unit and integration tests pass.
    runs-on: ubuntu-latest
    needs: integration-tests
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v4
        with: { version: "latest", enable-cache: true, cache-dependency-glob: "uv.lock" }
      - run: uv tool install snowflake-cli
      - name: Configure Snowflake CI connection
        run: |
          echo "$SF_PAT_TOKEN" > /tmp/sf_token.txt
          mkdir -p ~/.snowflake
          printf '[connections.ci]\naccount = "sfseeurope-wkot_demo1"\n\
user = "wkot"\nauthenticator = "PROGRAMMATIC_ACCESS_TOKEN"\n\
token_file_path = "/tmp/sf_token.txt"\n' > ~/.snowflake/config.toml
          chmod 0600 ~/.snowflake/config.toml
        env: { SF_PAT_TOKEN: "${{ secrets.SF_PAT_TOKEN }}" }
      - name: Deploy to Snowflake SiS
        run: scripts/30_deploy.sh -c ci
🚀
Full cycle completed! Your workflow is now: git commit (pre-commit runs) → git push (CI: tests pass + SiS redeploys) → visit the app URL to see the live update.
