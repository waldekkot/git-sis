Adding a Purge Feature
from Scratch, TDD-First

A concrete worked example of the full change cycle: design decisions, failing tests, implementation, AppTest gotchas, and shipping — 9 new tests, 100 % coverage maintained throughout.

What we're building

The ops console needs a "Purge Orders" button: a destructive action that deletes every row from the ORDERS table, logs the event to INGEST_LOG for auditability, and shows the operator a confirmation dialog before proceeding.

This page walks through every decision and every line of code in the order they were written — exactly as TDD demands.

Phase 1 — RED

Write failing tests before any implementation exists. ImportError is the first red.

Phase 2 — GREEN

Implement the minimum code to make every test pass. Nothing more.

Phase 3 — UI Layer

AppTest tests drive the Streamlit UI. Discover and resolve the @st.dialog gotcha.

Phase 4 — SHIP

Commit, push, CI green, SiS deploy. 55 tests, 100 % coverage.

def test_purge_orders_empties_orders_table(seeded_session, uuid_patch):  # noqa: ARG001
    """After purge, ORDERS table must be empty."""

    assert seeded_session.table(_cfg.ORDERS_TABLE).count() == 0


def test_purge_orders_returns_deleted_count(seeded_session, uuid_patch):  # noqa: ARG001
    """purge_orders() must return the number of rows that were deleted."""
    run_ingestion(seeded_session, str(uuid.uuid4()), num_rows=7)
    deleted = purge_orders(seeded_session)
    assert deleted == 7


def test_purge_orders_logs_purge_event_to_ingest_log(seeded_session, uuid_patch):  # noqa: ARG001
    """purge_orders() must log a PURGE_ORDERS event to INGEST_LOG."""
    run_ingestion(seeded_session, str(uuid.uuid4()), num_rows=3)
    purge_orders(seeded_session)
    log = seeded_session.table(_cfg.INGEST_LOG_TABLE).collect()
    purge_entries = [r for r in log if r["PROC_NAME"] == "PURGE_ORDERS"]
    assert len(purge_entries) == 1
    assert purge_entries[0]["STATUS"] == "SUCCESS"
    assert purge_entries[0]["ROWS_LOADED"] == 3


def test_purge_orders_on_empty_table_returns_zero(seeded_session):
    """Purging an already-empty ORDERS table returns 0 and does not raise."""
    deleted = purge_orders(seeded_session)
    assert deleted == 0
    log = seeded_session.table(_cfg.INGEST_LOG_TABLE).collect()

Step 3 — Implement purge_orders() (GREEN)

Add the implementation to app/lib/ingest.py. The key constraint: no session.sql(). The Snowpark local testing emulator supports only the DataFrame API, so TRUNCATE TABLE is out. Use DataFrame.delete() instead — it translates to DELETE FROM <table> and works in the emulator.

app/lib/ingest.py — additions (diff)
+ import uuid as _uuid          # added to existing imports

  PROC_NAME = "LOAD_SYNTHETIC_ORDERS"
+ PURGE_PROC_NAME = "PURGE_ORDERS"

+ def purge_orders(session: Session) -> int:
+     """Delete all rows from ORDERS and log a PURGE_ORDERS event to INGEST_LOG.
+
+     Uses DataFrame.delete() — the Snowpark API for row deletion.
+     Compatible with the local testing emulator (no session.sql() used).
+     """
+     # Count first so we can report it even after deletion.
+     rows_to_delete = session.table(_cfg.ORDERS_TABLE).count()
+
+     # Delete all rows using the DataFrame API.
+     # DataFrame.delete() translates to DELETE FROM  with no WHERE clause.
+     session.table(_cfg.ORDERS_TABLE).delete()
+
+     # Record the purge event in INGEST_LOG for auditability.
+     run_id = str(_uuid.uuid4())
+     now = datetime.datetime.now(datetime.UTC)
+     session.create_dataframe(
+         [[run_id, PURGE_PROC_NAME, "SUCCESS", rows_to_delete, None, None, now, now]],
+         schema=_LOG_SCHEMA,
+     ).write.mode("append").save_as_table(_cfg.INGEST_LOG_TABLE)
+
+     return rows_to_delete

      ⚠️
      

        Why not session.sql("TRUNCATE TABLE ...")?

        The Snowpark local testing emulator does not support raw SQL execution via
        session.sql(). Any code that uses it will work in Snowflake but
        fail in unit tests. The DataFrame API (.delete(), .count(),
        .write.mode("append")) is fully emulated — keep business logic in the API.

Step 5 — The @st.dialog + AppTest gotcha

    

      Test 3 (full purge flow) fails in a non-obvious way. Understanding why
      requires knowing how @st.dialog works internally.
    


    
    

    

      The critical constraint: the dialog function is only called when its opener
      button is True in the same script run. If you click
      "Confirm purge" in a separate .run(), the opener button is False,
      the dialog function is never entered, and "Confirm purge" is never rendered — so the
      click does nothing.
    


    

      ⚠️
      

        Broken pattern: clicking the two buttons in separate runs

        at.button[purge_idx].click().run()   # opens dialog

        at.button[confirm_idx].click().run() # does nothing — dialog not rendered!
      

    


    

      💡
      

        Working pattern — dual-click before a single .run()

        Mark both buttons as clicked, then call .run() once. The script
        processes the opener (True) → dialog is called → confirm (True) →
        purge_orders() runs → st.rerun() fires.
      

    

  

    

      
tests/unit/test_app.py — dual-click pattern

      
def test_purge_dialog_confirm_empties_orders_and_shows_success(snowpark_app):
    """Full purge flow: seed → Purge+Confirm dual-click → ORDERS empty + success.

    @st.dialog creates a fragment that only renders when its opener button
    is clicked in the SAME script run. AppTest solution: mark BOTH buttons
    (Purge orders + Confirm purge) as clicked before calling .run().
    """
    at, sess = snowpark_app
    # Seed 500 rows via the "Run ingestion" button
    with patch("lib.session.get_session", return_value=sess):
        at.button[0].click().run()
    assert sess.table(_cfg.ORDERS_TABLE).count() == 500

    # Open the dialog to discover the confirm button index
    purge_btn_idx = next(i for i, b in enumerate(at.button) if "Purge" in b.label)
    with patch("lib.session.get_session", return_value=sess):
        at.button[purge_btn_idx].click().run()
    confirm_btn_idx = next(i for i, b in enumerate(at.button) if "Confirm" in b.label)

    # Dual-click: mark both as clicked, then single at.run()
    at.button[purge_btn_idx].click()    # mark Purge as clicked  (no .run() yet)
    at.button[confirm_btn_idx].click()  # mark Confirm as clicked (no .run() yet)
    with patch("lib.session.get_session", return_value=sess):
        at.run()  # single run with BOTH buttons True

    assert not at.exception
    assert len(at.success) >= 1
    assert "500" in at.success[-1].value
    assert sess.table(_cfg.ORDERS_TABLE).count() == 0

    

  

    

      💡
      

        click() returns the button element, not AppTest.
        Chaining at.button[i].click().button[j].click() raises
        AttributeError: button. Call .click() on each button
        via at.button[i] separately, then call at.run() once.

def test_purge_dialog_shows_error_on_failure(snowpark_app):
    """When purge_orders() raises, _purge_error shown via st.error."""
    at, sess = snowpark_app
    purge_btn_idx = next(i for i, b in enumerate(at.button) if "Purge" in b.label)
    with patch("lib.session.get_session", return_value=sess):
        at.button[purge_btn_idx].click().run()
    confirm_btn_idx = next(i for i, b in enumerate(at.button) if "Confirm" in b.label)

    with patch("lib.ingest.purge_orders", side_effect=RuntimeError("disk full")):
        at.button[purge_btn_idx].click()
        at.button[confirm_btn_idx].click()
        with patch("lib.session.get_session", return_value=sess):
            at.run()

    assert not at.exception
    assert len(at.error) >= 1
    assert "disk full" in at.error[-1].value

    

    

      💡
      

        This is the one justified use of unittest.mock.patch on
        business logic: testing a controlled failure mode that the emulator
        can't trigger naturally.
      

    

  
Step 7 — The full UI implementation

    
The streamlit_app.py additions that make all five UI tests pass:

    

      
app/streamlit_app.py — Danger Zone section

      
from lib.ingest import get_kpis, get_run_history, purge_orders, run_ingestion

# ... (existing KPI + run history sections unchanged) ...

# --- Danger Zone -------------------------------------------------------------

@st.dialog("Confirm purge", icon="⚠️")
def _confirm_purge_dialog() -> None:
    """Modal confirmation before irreversible ORDERS deletion."""
    st.warning("This will permanently delete **all rows** from the ORDERS table.")
    st.caption("This action cannot be undone. The deletion will be logged to INGEST_LOG.")
    col1, col2 = st.columns(2)
    if col1.button("Confirm purge", type="primary", use_container_width=True):
        try:
            with st.spinner("Purging ORDERS..."):
                rows_deleted = purge_orders(session)
            st.session_state["_purge_result"] = rows_deleted
        except Exception as exc:  # noqa: BLE001
            st.session_state["_purge_error"] = str(exc)
        st.rerun()
    if col2.button("Cancel", use_container_width=True):
        st.rerun()


with st.expander("⚠️ Danger Zone", expanded=False):
    st.caption("Irreversible operations — use with care.")
    if st.button("🗑 Purge orders", type="secondary",
                 help="Delete all rows from the ORDERS table"):
        _confirm_purge_dialog()

# Surface purge result / error after the dialog closes and the app reruns.
# No st.rerun() here — KPIs are already refreshed by the dialog's own rerun.
if "_purge_result" in st.session_state:
    rows = st.session_state.pop("_purge_result")
    st.success(f"ORDERS purged — {rows:,} rows deleted.")

if "_purge_error" in st.session_state:
    err = st.session_state.pop("_purge_error")
    st.error(f"Purge failed: {err}")

    

  

    

      💡
      

        Why no second st.rerun() after the success message?
        The dialog calls st.rerun() itself after setting
        _purge_result. The full app reruns, KPIs refresh, and the
        success message is displayed. Adding a second st.rerun() would
        erase the success message before AppTest captures the final state.

What we learned

    

    
    
  

  

  
  

  

  
  

  

  

  

  
  

  

  
  

  

  

  
  

  

  
  

  

  
  

  

      
        

          Topic
          Lesson
        

      
      
        

          DataFrame.delete()
          The Snowpark API for row deletion; works in the local emulator. Never use session.sql("TRUNCATE") in code that must be unit-tested.
        

        

          @st.dialog + AppTest
          The dialog function only runs when its opener button is True in the same script run. Use the dual-click pattern: click both buttons, then call .run() once.
        

        

          click() return type
          Button.click() returns the Button element, not AppTest. Do not chain .button[i].click().button[j].
        

        

          Second st.rerun()
          Don't add a second st.rerun() after showing the success message — the dialog's own rerun already refreshed the KPIs, and a second one erases the message before AppTest captures it.
        

        

          Mock inventory
          The only justified mock on business logic is the error-path test: one patch("lib.ingest.purge_orders", side_effect=RuntimeError(...)) for a failure mode the emulator can't trigger naturally.
