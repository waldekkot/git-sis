Key concepts

The session seam

The app runs unchanged in two environments. A single try/except in app/lib/session.py picks the right connection: get_active_session() inside Snowflake, or a CLI-built Session locally.

Secretless pipeline (OIDC)

CI/CD authenticates to Snowflake with short-lived OIDC tokens via Workload Identity Federation — no passwords, private keys, or PAT secrets stored anywhere. Git auth uses the GitHub App OAuth2 flow (one-click per user, Snowflake manages token rotation). The result: zero stored secrets in the entire pipeline.

Why? Long-lived secrets are a liability in public repos. OIDC tokens expire in ~5 minutes and are scoped to this specific repository + environment. Even if somehow captured, they're useless after expiry.

Versioned releases + instant rollback

Pushing a vX.Y.Z git tag commits a named, immutable Streamlit version. Rollback is a single SQL statement (ALTER STREAMLIT ... SET DEFAULT_VERSION) — seconds, no redeploy required. Main-branch deploys ride the mutable LIVE version; tags immortalise stable releases.

Three deploy mechanisms

A. snow CLI push (CI/CD) — uploads code + creates objects behind a quality gate.
B. GIT REPOSITORY pull — Snowflake fetches from GitHub, zero CI required.
C. Workspaces — browser-based dev with private preview before publish.
All three are supported; the pipeline uses A for prod, devs choose B or C for iteration.

Three-tier dev loop

Tier 1 Unit tests — no Snowflake, zero credentials, ~3s (Snowpark local emulator + AppTest).
Tier 2 GitHub Actions CI — unit + lint + architecture guard + integration tests (OIDC).
Tier 3 Integration tests — real Snowflake, isolated temp schema, parallel (pytest-xdist).

Why this split? Tier 1 gives sub-second feedback during TDD. Tier 2 catches environment-specific issues without blocking your flow. Tier 3 validates against the real engine before prod deploy.

💡
Prerequisites: Python 3.11+, uv, snow CLI 3.14+, a Snowflake account (SYSADMIN + ACCOUNTADMIN access), and a GitHub account. No stored secrets needed — CI uses OIDC; git uses OAuth2.
